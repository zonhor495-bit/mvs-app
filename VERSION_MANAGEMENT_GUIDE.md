# 📖 Как добавить новую версию в MVS

Система версионирования MVS централизована в файле `src/website/versions.ts`. Это позволяет легко добавлять новые версии без переделки кода.

## Процесс релиза новой версии

### Шаг 1: Обновите `package.json`

Измените версию на нужную (например, с `1.1.8` на `1.1.9`):

```json
{
  "version": "1.1.9"
}
```

### Шаг 2: Добавьте запись в `src/website/versions.ts`

Откройте файл `src/website/versions.ts` и добавьте **новую версию в начало массива** `versionHistory` (т.е. самая новая версия — первая в списке):

```typescript
export const versionHistory: ReleaseEntry[] = [
  {
    version: '1.1.9',
    date: '15 августа 2026',
    title: 'Улучшение производительности',
    features: [
      'Оптимизирована работа с большими объёмами данных',
      'Улучшен интерфейс управления клиентами',
      'Добавлена быстрая навигация по клавишам',
    ],
    fixes: [
      'Исправлена ошибка при работе с экспортом данных',
      'Улучшена стабильность при работе с 10K+ записей',
      'Оптимизирована использование памяти',
    ],
  },
  // ... старые версии идут ниже ...
];
```

### Шаг 3: Добавьте размер файла в `fileSizes`

Добавьте размер нового установщика в килобайтах (приблизительно):

```typescript
export const fileSizes: Record<string, number> = {
  '1.1.9': 85,  // ← Новая версия (размер в МБ)
  '1.1.8': 84,
  '1.1.0': 84,
  '1.0.3': 82,
  // ...
};
```

Вы можете узнать точный размер из файла `build/win/MVSSetup-1.1.9.exe`.

### Шаг 4: Пересберите проект

```bash
npm run build
```

Это выполнит:
- Обновление `package-lock.json` с новой версией
- Перестройку веб-приложения с новой версией в `dist/`
- Перестройку Electron приложения

### Шаг 5: Создайте Windows установщик

```bash
npm run build:win
```

Это создаст файл `build/win/MVSSetup-1.1.9.exe` с автоматическим расчётом хешей и размеров в `build/win/latest.yml`.

### Шаг 6: Создайте GitHub Release (опционально)

1. Перейдите на https://github.com/zonhor495-bit/mvs-app/releases
2. Создайте новый релиз с тегом `v1.1.9`
3. Загрузите файл `MVSSetup-1.1.9.exe`
4. Скопируйте описание из `src/website/versions.ts`
5. Опубликуйте релиз

## 📋 Чек-лист для релиза

- [ ] Обновлена версия в `package.json`
- [ ] Добавлена новая версия в `versionHistory` (в начало!)
- [ ] Добавлена запись в `fileSizes` для нового размера
- [ ] Выполнена команда `npm run build`
- [ ] Выполнена команда `npm run build:win` (или только `npm run build:electron` для Electron сборки)
- [ ] Проверен файл `build/win/latest.yml` на корректность
- [ ] Проверен файл `dist/index.html` на наличие новой версии
- [ ] Создан GitHub Release с тегом `v1.1.9` и файлом установщика

## 🔄 Структура версии в `versionHistory`

```typescript
{
  version: string;           // Версия (например, "1.1.9")
  date: string;             // Дата выпуска (например, "15 августа 2026")
  title: string;            // Название релиза (например, "Улучшение производительности")
  features: string[];       // Массив новых функций
  fixes: string[];          // Массив исправлений ошибок
}
```

## 📡 Как это работает на фронтенде

1. **На странице загрузки (`/download`)**:
   - Отображается **первая версия** из `versionHistory` как текущая
   - Показаны её фичи в блоке "Что нового в этой версии"
   - Кнопка "📖 Что нового" ведёт на `/changelog`
   - Кнопка скачивания использует текущую версию из `__APP_VERSION__`

2. **На странице истории версий (`/changelog` или `/release-notes`)**:
   - Показаны **все версии** в порядке от новой к старой
   - Текущая версия выделена синей полосой и бейджем "Текущая версия"
   - Для каждой версии отображаются фичи и исправления
   - Кнопка "На GitHub" ведёт на GitHub Release для этой версии

## 🚀 Система автообновления

После создания GitHub Release с установщиком:

1. Electron приложение проверяет `build/win/latest.yml`
2. Если версия новее текущей, предлагает пользователю обновиться
3. Скачивает и устанавливает новую версию автоматически

**Важно**: Всегда обновляйте GitHub Release перед тем, как обновлять `latest.yml` на сервере.

## 💡 Советы

- Держите `versionHistory` отсортированной по датам (новые версии вверху)
- Пишите понятные названия фич и исправлений (пользователи это видят на сайте)
- Используйте одинаковый формат дат (например, "15 августа 2026")
- Регулярно обновляйте файл размеров в `fileSizes`, чтобы отображение было точным

## ❓ Часто задаваемые вопросы

**Q: Что если забыл обновить `fileSizes`?**
A: Будет использовано значение по умолчанию (84 МБ). Работать будет, но размер может быть неточным.

**Q: Что если добавил версию не в начало массива?**
A: На странице загрузки будет отображаться первая версия из массива. Убедитесь, что новые версии всегда добавляются в начало.

**Q: Влияет ли это на Electron приложение?**
A: Электронная версия отображается через `app.getVersion()`, которая читается из `package.json`. Система версионирования на сайте независима.

**Q: Как отследить, кто обновился на новую версию?**
A: Используйте Google Analytics или другой сервис для отслеживания. В `latest.yml` хранится количество загрузок через GitHub.
