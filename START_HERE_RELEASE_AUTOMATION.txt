🎯 HOW THE SYSTEM WORKS
═════════════════════════════════════════════════════════════════════════════

USER PERSPECTIVE:
  1. Install MVSSetup-1.1.0.exe on Windows
  2. Launch app
  3. See UpdateDialog: "Version 1.1.1 is available"

DEVELOPER PERSPECTIVE:
  1. Bump version in package.json (1.1.0 → 1.1.1)
  2. Commit: git commit -m "bump: version 1.1.0 → 1.1.1"
  3. Create tag: git tag v1.1.1
  4. Push tag: git push origin v1.1.1
  5. GitHub Actions automatically:
     ✅ Builds web (Vite)
     ✅ Builds Electron main + preload
     ✅ Creates Windows installer (NSIS)
     ✅ Publishes to GitHub Release
     ✅ Verifies all 3 assets are present
     ✅ Reports success or failure

📞 TROUBLESHOOTING
═════════════════════════════════════════════════════════════════════════════

Q: How do I check if workflows completed?
A: Visit https://github.com/zonhor495-bit/mvs-app/actions
   Look for "Build and Publish Electron Release" runs for v1.1.0 and v1.1.1

Q: How do I verify assets were published?
A: curl https://api.github.com/repos/zonhor495-bit/mvs-app/releases/latest
   Should show tag_name "v1.1.1" with 3 assets (latest.yml, exe, blockmap)

Q: How do I release a new version?
A: 1. npm version patch  (auto-bumps version)
      or
      Update version in package.json manually
   2. git tag v1.1.2 (or whatever new version is)
   3. git push && git push --tags
   Done! Workflow runs automatically.

Q: Can I test on macOS?
A: No, macOS cannot run Windows .exe files.
   The workflow runs on Windows CI runner, so build is tested there.
   Full install/update test requires actual Windows machine.

Q: What if workflow fails?
A: 1. Check GitHub Actions console for error logs
   2. Most common issues:
      • Node/dependency issues → Run npm ci locally to reproduce
      • Build errors → Check TypeScript compilation
      • Asset upload timeout → GitHub API rate limit or network
   3. Can re-run workflow manually via workflow_dispatch trigger
