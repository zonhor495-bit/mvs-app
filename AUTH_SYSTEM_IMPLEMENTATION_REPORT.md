## 🔄 Поток Работы

### Первый Запуск
```
1. App.tsx обнаруживает, что isAppInitialized() = false
2. Показывает InitSetup компонент
3. Пользователь вводит пароли для admin и manager
4. Пароли сохраняются в localStorage
5. Автоматический вход под администратором
6. FirstRunSetup для создания первой автомойки
7. Основное приложение загружает с роль "администратор"
```

### Последующие Запуски
```
1. App.tsx обнаруживает isAppInitialized() = true
2. Показывает RoleLogin компонент
3. Пользователь выбирает роль и вводит пароль
4. verifyPassword() проверяет пароль
5. При успехе - загружается приложение с выбранной ролью
6. setCurrentRole() сохраняет текущую роль в localStorage
```

### Переключение Ролей
```
1. Пользователь в основном приложении
2. Кликает на кнопку роли (👤 или 👑)
3. Выбирает другую роль из меню
4. Модальное окно запрашивает пароль
5. verifyPassword() проверяет пароль
6. При успехе - Layout срабатывает onRoleChange()
7. InternalApp обновляет user.role
8. Интерфейс обновляется в соответствии с правами
```

### Logout
```
1. Пользователь кликает "Выйти из аккаунта"
2. handleLogout() вызывается
3. clearSession() очищает сеанс пользователя
4. setAppState('role-login') возвращает на RoleLogin
5. Пароли остаются в памяти (можно войти снова)
```

### Admin (7 разрешений)
- VIEW_ORDERS - просмотр заказов

- VIEW_PRICING - просмотр прайса

- VIEW_ANALYTICS - просмотр аналитики
- VIEW_REPORTS - просмотр отчётов

### Manager (все разрешения включая)

- EDIT_PRICES - редактирование цен

- MANAGE_WAREHOUSE - управление складом

## 📝 Примечания

### Безопасность
- Пароли хранятся в localStorage (⚠️ не безопасно для production!)
- Рекомендуется в production использовать backend API для проверки паролей
- Рекомендуется использовать HTTPS и secure cookies

### Масштабируемость
- Система разрешений легко расширяется добавлением новых Permission значений
- Новые роли можно добавлять в ROLE_PERMISSIONS без изменения ядра
- Компоненты полностью переиспользуются без модификаций
