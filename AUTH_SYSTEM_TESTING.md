# Система Аутентификации - Инструкция по Тестированию

## Обзор

Система аутентификации была полностью переработана с использованием следующих компонентов:

- **InitSetup.tsx** - первоначальная настройка паролей для администратора и управляющего
- **RoleLogin.tsx** - экран выбора роли и ввода пароля
- **permissions.ts** - система разрешений на основе ролей
- **store.ts** - функции для управления состоянием и хранилищем
- **App.tsx** - обёртка для управления потоком аутентификации

## Поток Работы

### 1. Первый Запуск Приложения

1. **Экран InitSetup**:
   - Показывается при первом запуске приложения
   - Пользователь вводит 2 пароля:
     - Пароль администратора (минимум 4 символа)
     - Пароль управляющего (минимум 4 символа, отличается от администратора)
   - После подтверждения пароли сохраняются в localStorage

2. **Автоматический Вход**:
   - После сохранения паролей система автоматически входит под администратором
   - Переход на экран FirstRunSetup для создания первой автомойки

3. **FirstRunSetup**:
   - Форма для создания первой автомойки
   - Заполняется: название, владелец, часовой пояс, валюта, язык
   - После создания - переход в основное приложение

### 2. Последующие Запуски

1. **Экран RoleLogin**:
   - Выбор роли (Администратор или Управляющий)
   - Ввод пароля для выбранной роли
   - При неверном пароле - ошибка "Неверный пароль"

2. **Основное Приложение**:
   - Загрузка основного интерфейса с соответствующей ролью
   - Администратор видит только: Dashboard, Orders, Clients, Pricing, Cashier, Analytics, Reports
   - Управляющий видит все разделы

### 3. Переключение Ролей Во Время Сеанса

1. **Меню Переключения** (правый верхний угол):
   - Кнопка с иконкой текущей роли (👤 или 👑)
   - Меню содержит:
     - Администратор
     - Управляющий
     - Выйти из аккаунта

2. **Процесс Переключения**:
   - При клике на другую роль появляется модальное окно
   - Требуется ввод пароля для новой роли
   - При верном пароле - переключение на новую роль
   - При неверном пароле - ошибка и остаток на текущей роли

3. **Logout**:
   - При клике "Выйти из аккаунта" - очистка сеанса
   - Возврат на экран RoleLogin

## Тестовые Сценарии

### Сценарий 1: Первый Запуск

```
1. Запустить приложение (localStorage должно быть пусто)
2. Должен появиться экран InitSetup
3. Ввести пароль администратора: "admin123"
4. Ввести пароль администратора еще раз: "admin123"
5. Ввести пароль управляющего: "manager456"
6. Ввести пароль управляющего еще раз: "manager456"
7. Нажать "Создать"
8. Должен появиться FirstRunSetup
9. Заполнить данные и создать автомойку
10. Проверить, что загрузился основной интерфейс с администратором
```

### Сценарий 2: Последующий Запуск

```
1. Очистить localStorage (если нужно протестировать полный цикл)
2. Запустить приложение снова
3. Должен появиться экран RoleLogin
4. Выбрать "Администратор"
5. Ввести пароль: "admin123"
6. Проверить успешный вход
```

### Сценарий 3: Неверный Пароль

```
1. На экране RoleLogin выбрать "Администратор"
2. Ввести неверный пароль: "wrongpass"
3. Проверить ошибку "Неверный пароль"
4. Ввести правильный пароль: "admin123"
5. Проверить успешный вход
```

### Сценарий 4: Переключение Ролей

```
1. Войти под администратором (пароль: "admin123")
2. В правом верхнем углу нажать на кнопку роли (👤)
3. В меню выбрать "Управляющий"
4. Должно появиться модальное окно с запросом пароля
5. Ввести пароль управляющего: "manager456"
6. Проверить успешное переключение на управляющего
7. Проверить что видны все разделы (including сотрудники, склад и т.д.)
```

### Сценарий 5: Logout

```
1. Быть в основном приложении под какой-либо ролью
2. В правом верхнем углу нажать на кнопку роли
3. В меню выбрать "Выйти из аккаунта"
4. Должен появиться экран RoleLogin
5. Пароли должны остаться в памяти (можно войти снова)
```

### Сценарий 6: Ограничения Администратора

```
1. Войти под администратором
2. В боковом меню должны быть видны только:
   - Dashboard
   - Orders
   - Clients
   - Pricing
   - Cashier
   - Analytics
   - Reports
3. Остальные разделы должны быть скрыты или недоступны
4. Попытка зайти на недоступный раздел должна показать сообщение об ошибке
```

## Проверка Storage

### localStorage Keys

```javascript
// Проверить в браузере консоли:
console.log(localStorage.getItem('wd_is_initialized')); // true
console.log(localStorage.getItem('wd_auth_passwords')); // {"admin":"admin123","manager":"manager456"}
console.log(localStorage.getItem('wd_current_role')); // "admin" или "manager"
console.log(localStorage.getItem('wd_session')); // {"userId":"...","activeOrgId":"..."}
```

## Отладка

### Если что-то не работает

1. **InitSetup не показывается**:
   - Проверить `localStorage.getItem('wd_is_initialized')`
   - Должно быть `null` для первого запуска

2. **RoleLogin не работает**:
   - Проверить `localStorage.getItem('wd_auth_passwords')`
   - Должны быть сохранены оба пароля

3. **Пароли не проверяются**:
   - Проверить что `verifyPassword()` вызывается правильно
   - Сравнение должно быть строгое (===)

4. **Роли не переключаются**:
   - Проверить что `setCurrentRole()` вызывается
   - Проверить что InternalApp получает `onLogout` пропс

## Обновления Системы Разрешений

Система разрешений основана на enum Permission и ROLE_PERMISSIONS record.

### Администратор (7 разрешений)
- VIEW_ORDERS
- MANAGE_ORDERS
- VIEW_CLIENTS
- VIEW_PRICING
- PROCESS_PAYMENT
- VIEW_CASHIER
- VIEW_ANALYTICS
- VIEW_REPORTS

### Управляющий (все разрешения)
- Все из администратора +
- EDIT_SERVICES
- EDIT_PRICES
- MANAGE_EMPLOYEES
- MANAGE_WAREHOUSE
- MANAGE_SUPPLIERS
- И другие ~30+ разрешений

Для использования в компонентах:
```typescript
import { hasPermission } from '../permissions';
import { getCurrentRole } from '../store';

const role = getCurrentRole();
if (hasPermission(role, Permission.EDIT_PRICES)) {
  // Показать элемент
}
```

## Миграция Старого Кода

При использовании старых проверок вроде `user.role === 'admin'`:
- Заменить на `hasPermission(user.role, Permission.SPECIFIC_ACTION)`
- Это позволяет легче добавлять новые разрешения в будущем
